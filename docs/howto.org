#+TITLE: emu-gmm HOWTO --- wiring your application to the estimator
#+OPTIONS: toc:2 num:nil
#+SUBTITLE: What code you write, what the framework owns, and how they meet at estimate()

This is the integration guide. It explains the architecture at the level
you need to answer one question: *what do I have to hand to =emu-gmm=,
and what does it give back?* For the mathematical specification see
=docs/design.org=; for the asymptotic theory see
=docs/mcar-asymptotics.org=; for the full typed API see
=docs/api-sketch.org=. Runnable, copy-pasteable examples live in
=examples/= (see the table at the end).

* The one-sentence mental model

=emu-gmm= estimates a parameter \(\theta\) by driving a vector of
*moment conditions* to (approximately) zero:

#+begin_src text
  theta_hat  =  argmin_theta   E_mu[ psi(x, theta) ]'  V_mu(theta)^{-1}  E_mu[ psi(x, theta) ]
                               \__________________/    \______________/
                                  the moments you           the variance
                                  define (a vector)         the framework builds
#+end_src

You supply the *residual function* =psi= and *where the expectation is
taken* (a =Measure=). The framework owns everything statistical: the
criterion, the optimiser loop, the weighting matrix, the standard
errors, the over-identification (J) test, and the diagnostics. You read
the criterion and diagnostics off the =OptimizationResult= and inference
from =result.asymptotic()=; *you never recompute them by hand* (see
"Contracts that bite", below).

* What you supply vs. what the framework owns

| You write / choose                                   | The framework owns                          |
|------------------------------------------------------+---------------------------------------------|
| =psi(x, theta) -> (M,)=, the per-observation moment  | The criterion \(Q_\mu(\theta)\) and its minimisation |
| A parameter container (a small dataclass)            | The weighting matrix \(\Lambda = V^{-1}\) and its AD |
| A =Measure= (empirical / analytical / synthetic)     | \(\hat\theta\), asymptotic covariance and standard errors |
| A =CovarianceStrategy= (iid / clustered)             | The J-statistic, degrees of freedom, p-values       |
| /(optional)/ weighting, regularisation, optimiser    | Per-moment diagnostics (=N_j=, condition numbers)    |

The fit returns an =OptimizationResult=; its =asymptotic()= law supplies
the uncertainty estimates and p-values.

* The five pieces, and the code each one needs

** 1. The moment function =psi(x, theta) -> (M,)=

This is the heart of your application. It is a *pure, per-observation*
function: given one observation =x= (a length-=D= JAX vector) and the
parameters =theta=, it returns a length-=M= JAX vector of moment
residuals whose population expectation is zero at the truth.

#+begin_src python
import jax.numpy as jnp

def psi(x, theta):
    # x:     one observation, shape (D,)
    # theta: your parameter container (see piece 2)
    # return: shape (M,), the M moment residuals for THIS observation
    ...
    return jnp.stack([m0, m1, ...])   # length M
#+end_src

Contract:
- *Per-observation, not aggregated.* Return the residual for a single
  =x=; the framework applies =vmap= over the sample and forms the mean
  itself. Do *not* compute a sample mean inside =psi=.
- *Pure JAX, differentiable.* =theta= flows through =jax.jacfwd= /
  =grad=; use =jnp=, avoid Python branching on traced values, avoid
  pandas.
- =M= (the output length) is the number of moments and must satisfy
  =M >= K=, where =K= is the number of scalar parameters. =M == K= is
  just-identified (J is identically 0); =M > K= is over-identified (J
  tests the extra restrictions).
- *Labelled moments (optional).* If you return a =haliax.NamedArray=
  with a =Moments= axis, its labels propagate to the outputs; else pass
  =moment_names=("...", ...)= to =estimate=; else moments are named
  =m_0, m_1, ...=.

** 2. The parameter container

A small =@jdc.pytree_dataclass= whose leaves are the scalar parameters.
This is what =theta_init= is and what =result.theta_hat= comes back as.

#+begin_src python
import jax_dataclasses as jdc

@jdc.pytree_dataclass
class MyParams:
    beta: float
    gamma: float
#+end_src

Contract: by default, leaves are 0-d scalars living in flat
\(\mathbb{R}^K\). The leaf *names* become the parameter labels on
=result.asymptotic().cov()= / =.se()=. Constrained parameters (a scale
=sigma > 0=, a fixed-rank PSD block) are supported via the manifold
types =Positive=, =PSDFixedRank=, =Euclidean=, and =Product= (all
top-level exports): annotate the container with
=__emu_manifolds__ = {"sigma": Positive()}= and =estimate= dispatches
to =RiemannianLM= automatically.

** 3. A Measure: where \(E_\mu[\psi]\) is taken

The =Measure= says *what you are averaging over*. Pick one:

| Measure              | Use when                                              | You supply                                                        |
|----------------------+-------------------------------------------------------+-------------------------------------------------------------------|
| =EmpiricalMeasure=   | You have a dataset (the common case)                  | =x=(N,D)= data, =mask=(N,M)= observability, =weights=(N,)=         |
| =AnalyticalMeasure=  | The moment expectation has a closed form              | =expectation_fn(psi, theta) -> (M,)=                              |
| =SyntheticMeasure=   | Moments come from simulating a model (SMM-style)      | =n_sim=, =sampler(key, theta) -> (n_sim, D)=, a PRNG =key=         |

#+begin_src python
from emu_gmm import EmpiricalMeasure

measure = EmpiricalMeasure(
    x=x,                          # (N, D) jax array of observations
    mask=jnp.ones((N, M)),        # (N, M): 1 if moment j observable for row i, else 0
    weights=jnp.ones(N),          # (N,) sampling weights (1/inclusion prob); ones if none
)
# Convenience: EmpiricalMeasure.from_nan_aware(x) infers a mask from
# non-NaN cells (use only when the moment count M equals the data
# width D; otherwise build the (N, M) mask explicitly).
#+end_src

The =mask= is the *only* place per-moment observability lives. Different
moments may be observed for different numbers of rows; the framework
tracks the per-moment effective sample size \(N_j = \sum_i d_{ij} w_i\)
and folds it into the criterion and the variance (see "Contracts that
bite").

** 4. A CovarianceStrategy: how \(V_\mu(\theta)\) is built

Orthogonal to the Measure: the same =EmpiricalMeasure= pairs with any of
these without changing your =psi= or data.

| Strategy                              | Use when                                                       |
|---------------------------------------+----------------------------------------------------------------|
| =IIDCovariance()=                     | i.i.d. sampling (the default workhorse)                        |
| =ClusteredCovariance(cluster_ids, n_clusters)= | Within-cluster correlation (households in villages, etc.) |
| =AnalyticalCovariance= / =SyntheticCovariance= | Pair with the matching analytical / synthetic measure |
| =StratifiedCovariance(psu_ids, cell_ids, stratum_ids, ...)= | Stratified randomized designs (between-PSU Neyman) |
| =DesignAwareCovariance.from_design_mask(...)= | Design-based and sampled moments mixed in one vector |
| /(planned)/ =ReplicateWeightCovariance= | Replicate-weight designs (BRR / jackknife)               |

Caveat for the design-aware pair: under fixed stratum-mean heterogeneity
the coupled =DesignAwareCovariance= assembly is known to under-cover
(issue #145); prefer plain =StratifiedCovariance=, or pass
=couple=False=, until the v2.1 centering pass.

#+begin_src python
from emu_gmm import IIDCovariance, ClusteredCovariance

cov = IIDCovariance()
# or, clustered:
cov = ClusteredCovariance(cluster_ids=cluster_ids, n_clusters=50)  # cluster_ids: (N,)
#+end_src

** 5. (Optional) weighting, regularisation, optimiser: sensible defaults

You can omit all three; the defaults are good. Override only when you
know you need to.

| Knob             | Default                  | Alternatives                                          |
|------------------+--------------------------+-------------------------------------------------------|
| =weighting=      | =ContinuouslyUpdated()=  | =Identity()=, =Fixed(V0)=, =IteratedWeighting()=      |
| =regularization= | =DiagonalTikhonov()=     | (tune =kappa_target=)                                 |
| =optimizer=      | =optimistix_lm()=        | =scipy_lm()=                                          |
| =linear=         | =False=                  | =True= (affine moment: skip the optimiser, one step)  |

*Linear-in-parameters moments (OLS / linear IV / 2SLS).* When the moment
condition is affine in \(\theta\), the least-squares minimiser is one exact
Gauss--Newton step --- no iterative optimiser needed. Pass =linear=True= to
=estimate()= to take it (it wraps the optimiser in
=linear_solver(verify=False)=; the one-step form also wins under =vmap= /
=replicate=). =linear=True= *asserts* affinity of the /whitened/ residual, so it
requires a \(\theta\)-independent weight --- =Fixed(V0)= (the 2SLS fixed weight),
=Identity()=, or =IteratedWeighting()= --- and refuses the default
=ContinuouslyUpdated= (which makes even a linear moment a nonlinear program) and
manifold parameters, loudly. If you'd rather the one-step be /verified/ (taken
only when a first-order certificate holds, with an iterative fall-back), pass
=optimizer=linear_solver(verify=True)= instead. See =examples/panel_regression.py=.

* Putting it together: the smallest complete program

#+begin_src python
import jax, jax.numpy as jnp, jax_dataclasses as jdc
from emu_gmm import EmpiricalMeasure, IIDCovariance, estimate

@jdc.pytree_dataclass
class Params:
    p: float

def psi(x, theta):                       # one Bernoulli draw x (shape (1,))
    return jnp.array([x[0] - theta.p])    # M = 1 moment: E[X] - p == 0 at truth

x = jax.random.bernoulli(jax.random.PRNGKey(0), 0.5, (1000, 1)).astype(float)

result = estimate(
    model=psi,
    measure=EmpiricalMeasure(x=x, mask=jnp.ones((1000, 1)), weights=jnp.ones(1000)),
    covariance=IIDCovariance(),
    theta_init=Params(p=0.1),
)

print(float(result.theta_hat.p))   # ~ 0.5
law = result.asymptotic()
print(law.coef_table)              # estimate / std_error / t_stat / p_value (pandas)
print(float(result.objective_value), result.n_overid)
#+end_src

That is the entire integration surface: define =psi=, define =Params=,
build a measure, pick a covariance, call =estimate=.

* What you get back: =OptimizationResult= and =AsymptoticLaw=

The fit result holds optimization quantities; =result.asymptotic()= adds
the asymptotic inference readout. Read these, rather than recomputing them:

- =theta_hat= :: your =Params= type, filled with the estimates.
- =objective_value=, =n_overid= :: the realized criterion (J-statistic) and its over-identification degrees of freedom.
- =moment_covariance=, =weighting_matrix= :: the raw moment covariance and the realized inverse weight used by the criterion.
- =diagnostics= :: per-moment =N_j=, condition numbers, gradient norms.
- =converged=, =iterations= :: convergence flag and optimiser info.
- =to_pandas()= :: materialise optimization diagnostics for reporting.
- =result.asymptotic().cov()= / =.se()= :: asymptotic parameter covariance and standard errors.
- =result.asymptotic().coef_table= :: estimate / SE / t / p table (a pandas property).
- =result.asymptotic().J_pvalue= :: over-identification p-value when the fit is over-identified and efficiently weighted.

* Inference: which uncertainty tool?

=theta_hat= is half the answer; the other half is its uncertainty, and the framework gives you a small menu. All of it reads off the same pipeline --- you never hand-roll a variance.

| You want                                | Use                                  | Re-solves?      |
|-----------------------------------------+--------------------------------------+-----------------|
| parameter SEs, fast                     | =result.asymptotic().se()=           | no (analytic)   |
| parameter SEs / CIs, robust             | =cluster_bootstrap= \(\to\) =theta_boot= | *yes (refit)* |
| the \(J\) over-identification test      | =moment_wild_bootstrap=              | no              |
| inference robust to weak identification | =k_statistic= / =k_confidence_set=   | no              |
| SEs on functionals of \(AA'\) (gauge)   | =result.asymptotic().functional_se(f)= | no (analytic) |
| =n_boot= to a precision target          | =adaptive_bootstrap=                 | wraps the above |

** Two bootstraps, and why they differ

The distinction trips people up, so be explicit about it.

- =moment_wild_bootstrap= is /refit-free/. It perturbs the empirical moments with a wild weighting and reads off the \(J\) distribution (and, via the first-order delta, an approximate parameter distribution). It never re-solves the GMM problem, so it's cheap --- and it's the right tool for the \(J\) test.
- =cluster_bootstrap= is the /refit/ (re-estimation) parameter bootstrap. It resamples whole clusters with replacement, re-runs =estimate()= on each resample, and returns =theta_boot=, the bootstrap distribution of \(\hat\theta\) itself (Cameron, Gelbach & Miller 2008). It captures nonlinearity the delta method can't, and it's the one to reach for under few clusters, a boundary optimum, or a badly non-Gaussian sampling distribution.

The coin data above are independent; the groups below illustrate the API rather than a clustered data-generating process. Supply the actual sampling-cluster IDs for a clustered application.

#+begin_src python
import jax, jax.numpy as jnp, numpy as np
from emu_gmm import ClusteredCovariance, EmpiricalMeasure, estimate
from emu_gmm.inference import cluster_bootstrap

measure = EmpiricalMeasure(x=x, mask=jnp.ones((1000, 1)), weights=jnp.ones(1000))
cov = ClusteredCovariance(
    cluster_ids=jnp.repeat(jnp.arange(50), 20), n_clusters=50,
)
clustered_result = estimate(
    model=psi, measure=measure, covariance=cov, theta_init=result.theta_hat,
)
boot = cluster_bootstrap(
    model=psi, theta_init=clustered_result.theta_hat, measure=measure,
    covariance=cov, n_boot=99, key=jax.random.PRNGKey(1),
)
tb   = np.asarray(boot.theta_boot.array)[np.asarray(boot.convergence)]  # valid rows
se   = tb.std(axis=0, ddof=1) if boot.n_valid > 1 else None   # bootstrap SE
ci95 = jnp.quantile(tb, jnp.array([0.025, 0.975]), axis=0) if boot.n_valid else None
#+end_src

A refit that does not converge is stored as a =NaN= row --- not as its =theta_hat=, which on a resampled world that extinguished a rare moment's support is just =theta_init=, finite and unmoved (#209). =boot.convergence= names the event, =boot.zero_support= / =boot.tau_saturated= say why, and =boot.n_nonconverged= counts; reduce over the converged rows as above, or let =adaptive_bootstrap= exclude and count the =NaN= draws for you.

** The trick: a bootstrap is just =estimate()= on a resampled =Measure=

There's no monolithic =bootstrap_se= function, and that's deliberate. Because variance construction is orthogonal to integration, /resampling is a measure-construction concern/: =cluster_bootstrap= builds a fresh =EmpiricalMeasure= from the drawn clusters, pairs it with a matching =ClusteredCovariance=, and re-runs the ordinary pipeline. The refit bootstrap is a thin loop over =estimate()=, not a special variance routine --- which is exactly why a design-aware variant is cheap to add (the /stratified/ refit bootstrap is tracked in issue #155).

For large =n_boot=, build on the =build_estimator= factory rather than bare =estimate()= (see "Performance: estimating many times"), and let =adaptive_bootstrap= choose =n_boot= by targeting the Monte Carlo precision of the functional you care about. =examples/empirical_bootstrap.py= runs the wild and cluster bootstraps side by side.

* Contracts that bite (read before you debug)

1. *=psi= is per-observation and returns =(M,)=.* Returning an
   already-averaged scalar, or an =(N, M)= batch, is the most common
   wiring error. The framework does the averaging.
2. *Per-moment observability goes in the =(N, M)= mask, and nowhere else.*
   If different moments are observed for different numbers of units, set
   the mask accordingly; do *not* pre-aggregate or pad with a common
   \(N\). =emu-gmm= uses each moment's own \(N_j\) and folds it into the
   variance (\(1/(N_j N_k)\) normalisation), so the criterion is
   correctly scaled and \(J \to \chi^2_{M-K}\). (A balanced =mask=ones=
   hides this; if you ever see "my SEs look off under missingness",
   check the mask first.)
3. *Never recompute the criterion, J, or SEs yourself.* They are owned
   by the package and already carry the per-moment \(N_j\) scaling.
   Hand-rolling =J = (sqrt(N) * mean)' V^{-1} (sqrt(N) * mean)= or any
   "textbook" rescaling silently breaks under unequal \(N_j\). Read the
   fit result and its =asymptotic()= law. (See =design.org= "Scaling convention".)
4. *If an interface is missing something, file an issue; don't fork
   the statistic.* =emu-gmm= is meant to be the single correct
   implementation; a local reimplementation forfeits that for everyone
   downstream. Add the knob upstream.
5. *Float64 is on by default* (set at import). Don't disable it for a
   statistics workload.
6. *Shapes, at a glance:* =x= is =(N, D)=; =mask= is =(N, M)=; =weights=
   is =(N,)=; =psi= maps =(D,) -> (M,)=; =M= = number of moments, =K= =
   number of scalar parameters, =D= = observation width. =M= and =D= are
   independent (you can have more/fewer moments than data columns).

* Repeated sampling: custom procedures and parameter functionals

=emu_gmm.studies.replicate= owns the draw-and-fit loop, using =jax.random.fold_in(key, r)= for replicate =r=.
Its =dgp(rep_key)= can return any dataset type accepted by =run(theta_init, dataset)=.
The default recorder, =fit_record(result)=, reads an =OptimizationResult= through its asymptotic law.
For a multi-call procedure, supply =record(result, dataset) -> FitRecord= to retain the procedure's reported estimates, SEs, J quantities, and event flags.
The driver passes the same dataset object to the fit, record extractor, and extra-statistic extractors; it does not regenerate data for diagnostics.
Records must share their array shapes and static =param_names= / =J_dof= across replicates.
Custom procedures own their refitting and anchoring policy; =anchor_per_rep=True= remains the existing =build_estimator= / =Measure= path.

For a functional of an ordinary fit, extend the record at fit time with =fit_record(result, f=f, names=names)=.
The callable =f= takes the tuple returned by =result.components()= and returns a scalar or a one-dimensional array.
Its SE comes from the same =result.asymptotic().functional_se(f)= delta method, including all cross-covariances.
The original fit's J quantities, degrees of freedom, convergence, and named events remain in the record.
Without explicit =names=, functional coordinates are labelled =f_0=, =f_1=, and so on; explicit names must be distinct and match the output length.

For example, suppose =run= estimates a =PSDFixedRank(n, 2)= factor and a one-dimensional Euclidean leaf, and =truth_components= contains their population values:

#+begin_src python
import jax
import jax.numpy as jnp
from emu_gmm.studies import bias_sd, coverage, fit_record, replicate

def functional(components):
    A, phi = components
    gamma = A @ A.T
    return jnp.concatenate([
        jnp.linalg.eigvalsh(gamma)[-2:],
        jnp.atleast_1d(phi[0]),
    ])

records = replicate(
    run, dgp,
    n_reps=200,
    key=jax.random.PRNGKey(0),
    theta_init=parameters,
    record=lambda result, dataset: fit_record(
        result, f=functional, names=("lambda_small", "lambda_large", "phi")
    ),
)
truth = functional(truth_components)
bias = bias_sd(records, theta0=truth)
wald_coverage = coverage(records, theta0=truth, level=0.95)
#+end_src

The truth must be on the functional axis in the same order as the records.
The callable must be JAX-differentiable and gauge-invariant: a PSD factor enters through =A @ A.T=, rather than through its arbitrary rotation.
These summaries measure the coverage of the supplied Wald procedure; they do not establish validity at a rank boundary or at repeated eigenvalues, where the usual differentiability assumptions can fail.
A historical stack containing only ambient parameter estimates and marginal SEs cannot recover a functional's SE: the joint covariance is needed while the live fit is available.

=replicate_coupled(runs, dgp, ...)= forwards the same =record= and =statistics= extractors to every arm while retaining its shared =coupling_id= and fold-in schedule.
Each =statistics={name: extractor}= callable receives =(result, dataset)= and can return a scalar, vector, or tensor, provided its shape stays fixed across replicates.
For example, =statistics={"omega_eigenvalues": lambda result, dataset: jnp.linalg.eigvalsh(jnp.asarray(result.moment_covariance))}= records the eigenvalues of the fit's moment covariance.
The resulting =MCRecords.extra[name]= retains shape =(n_reps, *statistic_shape)= through pytree traversal and law persistence.
=records.to_pandas()= keeps scalar names, expands a vector to =name[0]=, =name[1]=, and a matrix to =name[0,0]=, =name[0,1]=, and so on in row-major order.
NaNs are preserved, and colliding output column names raise an error.

For separate shard jobs, pass =reps=range(start, stop)= instead of =n_reps=; exactly one selection is required.
The range must be nonempty, increasing by one, and within the uint32 fold-in domain.
Use the same DGP, master key, and explicit =coupling_id= across jobs, so each global index identifies the same draw.
=MCRecords.concat(shards, reps=range(full_start, full_stop))= validates metadata and exact coverage, sorts records and extras together, and preserves the global indices as the pandas index.
Without the expected =reps= range, concatenation checks the inferred contiguous interval and cannot detect a missing first or last shard.

=crn_pair= also accepts coupled arms with different parameter labels or J degrees of freedom, as in nested models.
Read their separate =param_names_a= / =param_names_b=; a common =param_names= query refuses ambiguity.
=paired_diff= requires arrays with identical shapes and an explicit Boolean =where= row selection, so different parameter dimensions require explicitly comparable coordinates or functionals.
Paired J differences describe the two procedures on identical draws; coupling alone does not provide a calibrated likelihood-ratio reference distribution.

* Performance: estimating many times

=estimate(...)= JIT-compiles on first call. If you estimate the *same*
model over many =(theta_init, measure)= pairs (Monte Carlo, bootstrap),
build the callable once with =build_estimator(...)= and reuse it, or
=jax.vmap= over the varying argument, so the compile cost is paid once.
Compile time is not the only cost: a bare =estimate()= loop rebuilds
its closures every call and leaks ~14 MB/call through JAX's global
caches (issue #139). The =build_estimator= path does not leak; if you
must loop =estimate()=, call =jax.clear_caches()= each iteration.
