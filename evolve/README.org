* What this is

The evolutionary-optimization harness pattern developed on the AggLC
project (Computation/evolve_pilot on its =evolve-pilot= branch),
instantiated for emu-gmm: LLM-evolved candidates propose ESTIMATOR
CONFIGURATIONS; a truth-anchored evaluator scores them against the
bundled Euler economy, whose ground truth is exact by construction
(beta = 0.96, gamma = 2.0; all population moments vanish at the truth,
plus a closed-form E[psi] oracle).  Nothing here runs evolution yet:
this directory is the harness, its battery, and a pre-registration
DRAFT.  Access mechanics (GCP project, engine, client checkout, ADC)
are shared with the AggLC pilot -- same =alphaevolve-exploration=
project; create a second Agent Platform engine (e.g. "emu-gmm") rather
than a second project.

* The pattern (what transferred, what changed)

Imported unchanged from the AggLC pilot:
- fixture cache with REGISTERED baselines (all-defaults config = score
  exactly 0);
- a budgeted probe oracle so candidates can search a little, never
  brute-force (8 calls, 6 replicates each);
- seed-scores-zero + determinism + budget + contract battery
  (test_harness.py G1-G6);
- HOLD-OUT fixtures at unseen PRNG keys AND unseen sample sizes,
  never scored during evolution.  The AggLC registered run's winner
  passed fitness spectacularly and FAILED hold-out transfer at H=4 --
  the hold-out is not optional;
- pre-registration with content-hash freeze before any run
  ([t6:prereg-hash-freeze-lesson] in the AggLC ledger), and amendments
  appended, never rewritten.

Changed for emu-gmm:
- Candidates return a WHITELISTED CONFIG DICT (weighting strategy +
  iteration policy + optimizer tolerances), not arrays and not code:
  the evaluator maps it to =Identity= / =IteratedWeighting= / CUE and
  =optimistix_lm= objects.  Strictly narrower attack surface than the
  AggLC pilot.
- The gate is GOLDEN-FIXTURE truth recovery (normalized RMSE over CRN
  replicates via jax.random.fold_in), NOT a soundness certificate.
  Per the adopted AggLC norm [t6:proc-verify-by-certificate] and its
  refinement (certificates verify instances; panels verify
  instruments): this gate verifies instances OF THIS DGP; claims from
  it cap at golden-fixture strength; instrument-level trust needs the
  hold-outs plus, for any adoption, a review of the winning config's
  statistical rationale.
- Compute honesty is a GATE, not a metric: mean iterations <= 3x
  baseline, all replicates converged, else score -1.

* Score (frozen at ratification; DRAFT until then)

Per fitness fixture: score = 1 - rmse/baseline_rmse, where rmse =
sqrt(mean over replicates of ((beta_hat-0.96)/0.96)^2 +
((gamma_hat-2.0)/2.0)^2), gates as above.  Combined = mean over
{euler_n800_k0, euler_n200_k1} (24 registered replicates each);
min_fixture_score reported.  Hold-outs {euler_n3000_k7,
euler_n100_k11} enter only the post-run battery: transfer bar
(DRAFT) >= half the fitness improvement on each hold-out, all gates
passing.

** Rationale review (why this is the statistically coherent outcome)

The Euler fixture is overidentified (M=3 assets, K=2 parameters), so
weighting matters asymptotically and efficient weighting (CUE /
iterated) must win as n grows -- which is exactly the observed sign
flip at n=3000.  At n<=800 the fitness fixtures sit in the
small-sample regime where CUE's sampling noise in V(theta) costs more
than efficiency buys (the known CUE-erratic-in-small-samples effect;
the n=100 hold-out shows it strongest).  The improvement the run
found is therefore a REAL small-sample phenomenon but not a
transferable config improvement; nothing in this whitelist can pass a
bar that demands persistence at n=3000.  Defaults (CUE + LM at
rtol=atol=1e-8) stand.

Byproduct observation (compute, not statistics): identity weighting
converges in ~12 LM iterations vs ~19 for CUE at equal (100 percent)
convergence -- consistent with its simpler objective -- and iterated
at n=3000 needed only ~9.6.  No action; recorded for reference.

** Score and gates

Per fitness fixture, with ADVERSARIAL accounting (every registered
replicate in the denominator; breaking hard replicates always hurts):

- cov_eff[k] = #{reps: converged AND finite se_k AND truth_k in the
  95 percent Wald CI} / n_reps
- rej_eff = #{reps: not converged OR non-finite J_pvalue OR J_pvalue
  < 0.05} / n_reps
- err = mean_k |cov_eff[k] - 0.95| + |rej_eff - 0.05|
- score = 1 - err/err_baseline; combined = mean over the two fitness
  fixtures; min_fixture_score reported.

Gates, RELATIVE to the registered baseline (absolute gates are
unusable in a regime that breaks replicates for everyone): n_used >=
baseline n_used; mean iterations (over used reps) <= 3x baseline.
Gate failure or contract violation = -1.  Probe oracle: 6 calls x 12
replicates of =fb_few_eps_k31=.

** Bottom line and adoption path

1. REGISTERED claim (run 2): the evolution found nothing; defaults
   beat every evolved candidate.  Negative result stands as
   registered.
2. EXPLORATORY-but-registered-metric claim (sweep + hold-outs):
   =DiagonalTikhonov(kappa_target ~ 1e3)= dominates the 1e6 default
   in the binding regime -- better convergence, better coverage,
   near-nominal J size -- transfers to an unseen milder-binding spec
   above the bar, and is bit-identical to the default on healthy
   data.  Claims cap at golden-fixture strength on this DGP family;
   a default change in emu-gmm needs EL's rationale review and its
   own confirmatory pass (the natural vehicle: an emu-gmm issue with
   this section attached).
3. Interface findings for the package: #201 (fixed-k two-step flagged
   non-converged; iterated_status not surfaced).  The registered
   metric inherited those semantics -- under flag-blind accounting
   even the baseline's err drops ~30 percent (see reference arms) --
   so any run 3 should decide deliberately which accounting it
   freezes.
4. Process lessons for future runs: the problem-text hint is part of
   the instrument (a wrong "iterated is steadier" hint sent 64/68
   candidates into a gated family); a whitelist boundary the sweep
   trend points AT (kappa=1e2 here) should trigger a bounds review
